AI-WORKFLOW · 图解

任务怎么流转

人写任务。AI 先只读；有歧义就停下来等你批准。改代码、送审之后，审查和合并仍由你做。AI 不合并、不 push、不删除 worktree。

执行规则以 README.md 为准

01 · 初始化

摆好任务池

在目标仓库的会话里说一次。只生成 .ai-workflow/，不改项目其他文件。

/ai-workflow init

02 · 整理任务

先出草稿

手写，或让 AI 拆 list/ 里的清单。你没明确要写入之前，不会进 inbox。

/ai-workflow task …

03 · 执行任务

领取一条

只领 inbox 里 status: new 的任务。讨论中和阻塞中的不能领。

/ai-workflow 处理 T-20260101-001
1 / 7
inbox 收件 doing 进行 review 审查 done 归档 色条是任务文件所在目录。审查通过后仍留在 review。

inbox · status: new

你怎么操作

下面按三条路径写。字段和命令的细节以 README.md 为准，配置在 CONFIG.md，任务格式在 TEMPLATE.md。

主路径

  1. 复制 TEMPLATE.md 为 inbox/T-20260101-001.md。id 与文件名一致，status: new。验收标准写可执行的命令；没核实的写 TODO。
  2. 说 /ai-workflow 处理 T-20260101-001。AI 加锁、把文件移到 doing、准备分支 ai/T-20260101-001 的 worktree。
  3. AI 只读探索，不改业务代码。没有重要歧义就直接实施。
  4. AI 只在 worktree 里改代码，把命令、目录、退出码、结果写入「验证记录」。没跑就写「未运行」。risk: high 只出方案，不改代码，送审时不能有 commit。
  5. 工作区干净、验证记录非空后送审，文件进入 review。到这里停止，不合并。
  6. 你看 diff 和验证记录，明确说审查通过。文件仍留在 review。
  7. 人工合并由你执行。告诉 AI 目标分支、合并提交、方式和你的原话。核对通过后才进入 done。

遇歧义

  1. 业务口径、接口、数据、权限、兼容或范围说不清时，AI 不能靠默认假设开工。
  2. AI 写「讨论」，把 status 改为 needs-discussion，文件移回 inbox，删除锁。worktree 和已有 diff 保留。
  3. 你补全「方案」。AI 计算方案正文的 sha256，写上 plan_version。
  4. 你明确说「批准版本 N」。只写方案，或 AI 说可行，都不是批准。
  5. 你要求恢复后，AI 重新计算 sha。版本、sha、批准人和原话一致，才回到 doing 继续做。
  6. 方案改过，或版本对不上，旧批准作废，不能恢复。

阻塞

  1. 做不下去，或你拒绝审查：status 改为 blocked，文件回到 inbox，删除锁，现场保留。
  2. blocked 和 needs-discussion 都在 inbox，但不能当新任务领取。
  3. 你补充信息并确认可以重做后，把 status 改回 new，才能再次领取。
  1. 1. 任务由你写

    /ai-workflow task 默认只给草稿。你确认后才写入 inbox，仍然不领取、不实现。

  2. 2. 批准要说出版本

    只有「批准版本 N」算数，而且只用于从讨论恢复。主路径没有歧义时不需要这一步。

  3. 3. 审查通过 ≠ 合并

    通过后 status 是 review_approved，人还没合并，文件留在 review。

  4. 4. 人工合并才归档

    merged_commit 必须在目标分支上。squash / rebase 不能用 sha 证明内容相同，必须写明。

文件停在哪

inbox

new 可领取。needs-discussion 与 blocked 不可领取。list/ 只放清单，没有状态。

doing

claimed。同时有锁 .locks/任务id/，以及 worktree .ai-worktrees/任务id/。

review

needs_review 等人看。review_approved 是人已通过、尚未合并。两态都在这里。

done

done。有目标分支和合并提交证据。无代码任务在你确认后也可以归档。不删除分支和 worktree。

不会自动发生

  • 不合并、不 push、不建 PR、不改 CI、不发版。
  • 不删除 worktree 或分支，不 reset 你的改动。
  • 锁已存在就停。异常退出留下的锁，由人确认后删除。
  • 不覆盖已有任务文件，不自动迁移旧 .ai/。
  • 不把任务状态偷偷提交进业务分支。
  • 验收标准不能自行放宽。没跑的检查写「未运行」。
